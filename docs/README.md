# gitMaster 文档索引

本项目面向 Git 初学者，提供 Windows/macOS 图形化桌面客户端。英文品牌为 **gitMaster**，中文名尚未最终确认。

当前已完成 M2/M3 计划内功能及 HTML 工作台实现。macOS 核心/适配自动测试、前端检查和浏览器夹具已有证据；Windows 本轮编译/实机、macOS 完整原生交互、真实认证网络等无法执行项按用户授权跳过，详见验证记录。M1 的历史平台结果不代表新写功能已通过同等验收。

## 阅读顺序

1. [需求与实施计划](spec-plan.md)：产品总览、阶段和历史验收基线；第 9 节保留旧 M2 草案。本轮执行基线为 [M2 + M3 合并开发 spec/plan](m2-m3-spec-plan.md)，包含已实现的本地操作、远端协作、冲突处理和 HTML 工作台，以及逐项验收状态。
2. [架构设计](architecture.md)：React、Tauri、独立 Rust 核心的职责和 SwiftUI 演进路线。
3. [接口与数据模型](interfaces.md)：已实现接口与未来接口约束。
4. [界面与交互规范](ui-design.md)：新手工作流、视觉材质、动效和无障碍要求。
5. [开发与编译环境](development.md)：Windows/macOS 安装软件、官网和常用命令。
6. [测试与验收](testing.md)：工程检查、真实临时仓库测试和 UI/平台验收边界。
7. [发布与安全边界](release-security.md)：系统 Git、凭据、打包、签名、更新。
8. [分阶段验收记录](verification.md)：分阶段记录实际执行结果及未验证项。

## 文档维护

- 先变更需求和接口，再实施代码；总计划保留阶段索引，本轮 M2/M3 的 spec 与 plan 合并维护于 `m2-m3-spec-plan.md`，不重复维护两套执行计划。
- 区分“已实现”“规划”“未验证”，不得把规划功能描述为现有能力。
- M1 为历史只读基线；M2/M3 写入必须经过确认计划，认证复用受信任的系统组件。Git 安装器、凭据存储和 SwiftUI 客户端仍未实现。
- 按用户本轮确认，保留现有项目骨架，代码、`docs/`、`AGENTS.md` 与 README 一同纳入版本管理。后续功能开发仍需单独授权。
