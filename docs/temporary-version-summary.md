## 1. 功能优化

本次保存 Windows 性能治理、提交图交互和诊断日志的阶段成果。历史摘要改为整页批量查询，引用头通过标准输入传递，减少逐提交启动 Git 的开销及 Windows 命令行长度风险。首次加载优先历史，写入能力按需读取；文件监听与版本标记替代无变化窗口切回时直接重读 Git。

提交图接入 d3-force，实现节点关联受力、柔性布局和漂浮，画布统一调度模拟；日志支持 Error 至 Trace 五档、跟随构建环境、即时生效及持久化，开发默认 Trace、生产默认 Error。补充 Windows 进程回收等待、机器错误码，以及日志目录物理路径处理。

**这是未完成故障修复的临时源码版本。** 最新日志中分支准备仍失败，准备耗时约 31.4 秒；1GB 磁盘缓存、完整阅读器优化及整体性能目标仍属后续工作，不能据此宣称基本 Git 操作已全部流畅可用。

## 2. 设计思路

- Tauri 为当前正式版技术主线，达标可长期保留；原生 Windows/macOS 客户端是后续可选演进，浏览器预览用于开发测试。
- Git 仍由独立 Rust 核心执行；前端调度与图形模拟不改变真实提交关系或写入授权。
- notify 负责文件监听，官方 tauri-plugin-log 负责日志输出，复用成熟工具并保持日志与业务结果独立。

## 3. 核心代码流程

1. 打开仓库 → 注册监听并读取状态 → 批量冻结/读取历史 → 按需读取分支及写能力。
2. 文件变化 → 版本标记 → 合并刷新；焦点恢复核对版本，监听不可靠时低频核实。
3. 节点拖动 → 力模拟沿真实连接传播 → 更新展示坐标；日志设置 → 持久化 → 动态过滤及文件轮转。

## 4. 重要问题点

- 分支失败发生在确认预览之前的隔离环境捕获；当前证据指向私有 git init。退出码 1 在上层丢失，stderr 内容未记录，根因还需受控复现。
- 首次指纹检查耗时约 18 秒；需分解路径检查、子进程启动和回收成本。不能依赖延长超时或删除安全检查解决。
- 日志目录存在 Windows 启动环境虚拟化差异；该问题与分支初始化失败不能未经验证就归为同一原因。

## 5. 防御与兜底措施

- 历史批量解析核对字段数和冻结 OID 顺序；迟到响应及切换仓库后的旧监听结果被隔离。
- 隐藏窗口保留脏标记，监听异常使用低频核实；写入继续经过准备、确认、队列与状态核实。
- 日志采用固定字段，不记录原始命令输出、凭据和文件内容；轮转额外维护同秒备份，容量为维护后收敛。
