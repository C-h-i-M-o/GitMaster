# 界面与交互规范

## 产品气质

精致、安静、清晰。品牌暂用 gitMaster；中文名不在本轮定案。M0 为浅色起始页面，深墨文字、淡青背景、克制的局部半透明；不制作假仓库仪表盘。

## 信息架构（产品规划）

- 项目入口：最近项目、打开项目、下载项目；缺少 Git 时转入环境引导。
- 工作区：项目/分支导航、文件变更、差异详情、保存版本面板。
- 历史：先用清晰列表，复杂提交图在有实际需求时增加。
- 设置：Git 路径、外观、动效、应用信息；凭据不使用普通配置文件保存。

## 新手交互

- 主文案使用“保存版本”“上传版本”等任务语言，补充 Git 术语帮助学习。
- 先让用户理解本机与远端的区别，再提供协作动作。
- 不把 fetch、pull、push 合成不可解释的一键操作。
- 丢弃内容、恢复文件、撤销提交分别展示作用范围和后果。
- 冲突时展示冲突文件与可执行下一步，不承诺自动解决所有冲突。
- 二进制文件只显示可用信息，不伪造文本差异或语义合并。

## 材质与动效

- 玻璃效果仅用于导航、工具条或浮动控件；阅读区域保持高对比背景。
- M0 使用 CSS 透明度/模糊，不声称是真正 Apple Liquid Glass，不读取桌面图像制造折射。
- 动效优先 transform/opacity；交互反馈建议 120–180ms，面板过渡 180–260ms。
- Motion 用于必要的入场/布局转换；不同时引入另一套动画框架。
- 不给每一行文件添加昂贵的背景模糊；长列表先虚拟化再考虑入场动画。
- 支持 `prefers-reduced-motion`；提供清晰键盘焦点、语义标题和状态反馈。
- 当前最低窗口尺寸为 860×620 CSS 像素；浏览器窄屏仍应可读，不据此声称支持移动端。
- 动效目标为参考机器上接近 60fps，必须实测；不把库宣传指标作为项目验收结果。

## 平台演进

Windows/macOS 的 WebView 分别验证。未来 SwiftUI 使用系统材质时保留整体颜色和层次，不逐像素照搬 CSS；旧系统有清晰回退。当前使用原生窗口边框，正式自定义标题栏需另行验证拖拽、缩放和辅助功能。

## M1 已实现交互

环境面板展示真实版本、规范路径和来源，支持重新检测、选择 Git、恢复自动检测及固定官网入口。仓库区域展示根目录、HEAD/操作状态和四组文件，按需读取单栏差异。列表初始显示每组最多 200 条，继续加载每次追加 200 条；差异文本区域支持键盘焦点和滚动。

加载中禁用互相冲突的操作；刷新失败保留旧快照并标记过期；差异失败保留所选文件并明确提示刷新重试。文本使用 React 文本节点，二进制、冲突、子模块、编码不支持和截断均有中文说明。没有提交/推送/解决冲突按钮。
