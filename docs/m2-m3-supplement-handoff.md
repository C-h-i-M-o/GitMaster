## 4. 核心流程、约束与兜底

1. 刷新/同步：明确目标 → FetchAll → 等待已核实终态和本地刷新 → 重新签发远端标识 → 核对原仓库、分支、上游和干净状态 → 判断差距 → 执行一次性写计划。结果未知不自动重放；发布或设置上游成功后即使后续失败，也保留已完成步骤。
2. 差异：签发的 changeId、比较侧、快照与 contextLines → Rust 受限差异读取 → 统一行号/增删展示与折叠。旧请求迟到不能覆盖新选中文件；默认 3 行上下文，最多请求 2000 行，返回仍限 1 MiB/5000 行。
3. 文件编辑基础：当前文件清单重新绑定 fileId → 读取完整文本和版本 → 独立草稿 → 保存前重读基线 → SaveFile 一次性任务 → 等待真实终态后确认提交文本。保存期间新输入保留；外部变化、未知结果和读取失败不丢草稿。
4. 设置：读取快照/revision → 六类共用草稿 → 校验完整模型 → 原子保存 → 应用已保存值。默认终端 profile 删除前必须明确选择替代项；保存 profile 本身不启动 shell。

文件编辑支持上限 2 MiB 的受支持 UTF-8 文本；混合换行、二进制及不支持编码拒绝可保存模型，但不据此禁止普通只读预览。项目文件树目前仍来自最多 10000 项/8 MiB 的平面清单，并非目录懒加载。外部打开首版限 VS Code、系统文件管理器、系统终端，不提供 Git Bash/WSL 专用入口或任意外部命令模板。

提交写守卫增加完整索引身份核对，避免状态字母不变但内容重新暂存后接受旧页面。FetchAll 使用私有下载与旧 OID 条件事务更新跟踪引用，不 prune、不自动取标签。日志不保存令牌、私钥、凭据 URL 或任意终端正文。
