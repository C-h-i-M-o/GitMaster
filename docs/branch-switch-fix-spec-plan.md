# Windows 分支切换失败修复方案（Spec + Plan）

日期：2026-09-23。状态：诊断与方案已整理，修复尚未实施。

本轮仅编写文档并保存临时版本，不修改业务代码。后续实施按任务逐项执行，可使用 executing-plans 技能；本文件合并需求与计划，关联总计划第 12、13 节。

## 1. 目标与范围

恢复 Windows Tauri 应用的分支准备与切换闭环，保留原有写前校验、用户确认、仓库写队列和结果核实。先修复已定位的准备失败，再优化准备耗时。不得通过强制切换、忽略脏文件、跳过并发校验或扩大超时掩盖问题。

技术栈沿用独立 Rust 核心、Tauri 2、React/TypeScript，不新增依赖。真实写测试仅使用专用临时仓库，不切换用户的业务仓库。当前临时提交不是安装包、正式发布或性能达标证明。

## 3. 调用链与候选原因

`prepare_local_write → prepare_switch_branch → branch_fingerprint → checkout_tree → CapturedCheckout::capture → CapturedTree::capture → private_query → run_isolated_git`。

相关源码：

- [branches.rs](../crates/gitmaster-core/src/git/branches.rs)：准备、指纹比较、生成确认计划与执行入口。
- [checkout.rs](../crates/gitmaster-core/src/git/checkout.rs)：临时仓库捕获与初始化；当前 private_query 将失败简化为通用错误。
- [process.rs](../crates/gitmaster-core/src/git/process.rs)：隔离环境及进程预算。
- [process_windows.rs](../crates/gitmaster-core/src/git/process_windows.rs)：Windows 启动、管道和回收。
- [write_guard.rs](../crates/gitmaster-core/src/git/write_guard.rs)：路径、索引、属性及并发校验。
- [error.rs](../crates/gitmaster-core/src/git/error.rs)、[diagnostics.rs](../crates/gitmaster-core/src/diagnostics.rs)：安全诊断字段与阶段计时。

优先复核以下变量，每次只改变一个条件：

1. 初始化时已有 `GIT_OBJECT_DIRECTORY` 指向源仓库 common_dir/objects；验证该绑定与 Windows 路径形式是否导致失败。
2. 临时目录中的中文、空格、短路径与扩展路径前缀，以及启动环境存在目录虚拟化时父子进程看到的目录是否一致。
3. 隔离环境中的 NUL 全局/系统配置路径、捕获的配置白名单和 Git 可执行文件版本。
4. 相同 executable、cwd、参数和环境下，自定义 Windows 启动器与标准进程启动的差异。普通终端直接执行 git init 成功不等于应用同环境成功。

## 4. 修复接口与约束

继续使用现有 `OperationError { code, retryable, diagnostic? }`，不扩大前端命令权限。

- 保留 `GIT_EXECUTION_FAILED` 错误码；初始化失败附加白名单 `diagnostic.stage = checkoutInit`、真实 `exitCode`，仅确有系统调用失败时附加 `osCode`。
- 在 error.rs 的阶段白名单加入 checkoutInit，未知阶段仍映射为 gitQuery；不得直接把任意字符串当阶段名。
- 日志保留关联 id/parent、固定操作类别、耗时、退出码和输出字节数，保证 Error 档也能看到失败阶段与退出码。
- 原始 stderr 仅在受控复现中本地检查。生产日志不记录原文、完整参数、仓库绝对路径、URL、配置值或凭据；如增加原因分类，只允许固定枚举，未知内容归为 unknown。
- 用户提示为“分支切换准备失败：临时仓库初始化失败（退出码 1）”，按实际码生成；不能提示“已切换”。可重试不代表自动重放写操作。
- 保留 prepare 返回预览、用户确认后 execute 的契约。缓存不得成为写授权，不取消执行前状态核实。

## 5. 实施任务与文件范围

### 任务一：建立可复现诊断

涉及 checkout.rs、error.rs、diagnostics.rs；仅在需要区分进程耗时时改 process.rs / process_windows.rs。

- [ ] 在现有 Rust 模块测试中增加初始化非零退出用例，先证明当前上层丢失 exitCode；断言修复后 stage=checkoutInit、exitCode=1，且不包含原始输出。
- [ ] 为配置读取和私有初始化分别记录固定阶段，保留父子关联；不是把所有退出码 1 都认定为故障，查询允许的“未找到”结果仍遵循原契约。
- [ ] 使用专用临时源仓库复现实际隔离参数。分别比较对象目录绑定有/无、普通/中文空格路径、扩展路径、标准/自定义启动器；保留相同 Git 版本与环境。
- [ ] 对启动环境有/无目录虚拟化分别检查子进程目录可见性；没有环境条件的组合单列未验证。
- [ ] 记录可复现条件及经过人工脱敏的原因分类，不把真实日志或本机配置复制进仓库。

验收：能从一次失败日志直接判断初始化阶段及真实退出码；最小用例能稳定失败，修复后同用例通过。无法复现时只交付诊断增强，不能宣称根因已修复。

### 任务二：按复现结果修复私有初始化

主要文件 checkout.rs；只有证据指向共享执行层时才修改 process.rs / process_windows.rs。

- [ ] 如果证实初始化阶段的源对象目录绑定导致失败，将“创建私有仓库”和“访问源对象”分开：初始化使用私有目录，后续确有需要的命令才绑定源对象；重新核对所有 private_query 调用用途。
- [ ] 如果证实路径表示或虚拟化导致失败，仅在相应边界规范化路径，验证父子进程访问同一目录；不硬编码用户名、Codex 包路径，不通过有损字符串转换处理路径。
- [ ] 如果证实启动器问题，先添加等价参数/环境回归用例再修复；保留 Job 回收、句柄限制、输出上限与取消行为。
- [ ] 验证失败后私有临时目录清理，以及源仓库 HEAD、refs、index、config、对象目录和工作文件均未被准备操作改变。
- [ ] 在临时仓库完成准备 → 预览 → 确认 → 切换 → 真实状态核实，断言目标分支和文件内容正确。

验收：初始化失败复现通过；后续第二次指纹检查和真实执行也通过。不能仅以 git init 成功代替整个切换验收。条件分支不是同时实施的多套修复，只保留证据支持的最小改动。

### 任务三：优化准备耗时

主要文件 write_guard.rs、branches.rs；测量确有需要时涉及 process.rs / process_windows.rs。前端进度或提示放现有 .ts hook，TSX 仅展示。

- [ ] 分别测量排队、创建进程、Git 执行、管道排空、进程回收、路径检查、属性读取与指纹比较；日志仅输出阶段、计数、耗时。
- [ ] 对同一次准备中的重复查询和祖先目录检查做去重或批处理；涉及文件身份的复用必须有明确有效期和变化检测，不能跨操作盲用。
- [ ] 保留脏工作区、忽略文件碰撞、目标 refs 变化、worktree 占用及执行前校验；不以静态缓存替代这些检查。
- [ ] 将准备、等待确认、执行、核实分开显示；迟到响应不得覆盖新会话，失败后恢复操作入口但不自动切换。
- [ ] 同一硬件、仓库和构建模式记录优化前后分布。现有 31423ms 是失败样本，只用于失败链路基线，不当作成功切换基线。

验收：普通小型临时仓库准备 P95 ≤2 秒，至少 20 次；大仓库单列文件数、引用数、构建模式、成功率及各阶段 P50/P95，不在没有成功基线前宣称达标。当前单次小 Git 调用约 0.5–0.98 秒只能说明链路慢，不能直接归因于 Git 或杀毒软件。

## 6. 回归与交付标准

| 用例                                             | 预期                                                      |
| ------------------------------------------------ | --------------------------------------------------------- |
| 干净仓库，两分支文件不同                         | 确认后切换，HEAD/文件/界面与目标一致                      |
| 初始化拒绝、无权限、临时目录不可见               | 准确阶段及机器码，原仓库不变，临时资源释放                |
| 中文、空格、扩展路径和 linked worktree           | 支持范围内闭环成功；不支持时稳定拒绝且不写入              |
| SHA-1、SHA-256                                   | 在对应 Git 支持条件下分别验证，不混用对象格式             |
| 准备后外部修改、目标分支移动、index.lock         | 拒绝过期计划或占用状态，不覆盖用户文件                    |
| 脏工作区、忽略文件碰撞、分支被其他 worktree 占用 | 保留现有拒绝行为                                          |
| 重复点击、取消、切换仓库、执行响应丢失           | 不重复写，旧结果不污染新会话；未知结果先核实              |
| Error/Trace、日志写入失败                        | Error 可定位失败；各档无敏感信息，日志故障不改变 Git 结果 |

实施后运行相关 Rust 回归，再执行 cargo fmt、核心测试、桌面检查；涉及前端时执行 pnpm typecheck、build、format:check。测试全套若存在旧失败，逐项记录，不扩大超时或删除断言来制造全绿。Windows Tauri 实际交互独立验收，浏览器替身和 macOS 历史结果不能替代。

最终在 verification.md 写明复现、修复、测试命令、通过/失败和未覆盖环境。本轮只完成该方案，不代表以上复选项已执行。
