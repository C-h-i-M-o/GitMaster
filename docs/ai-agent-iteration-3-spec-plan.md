# AI Agent 第三阶段：设置、错误恢复与 Git 超时

日期：2026-11-13。状态：**老大已确认，已授权按本文开发，实施中**。

本文合并需求规格、接口与状态设计、实施计划和验收标准。目标是在既有 Agent 能力上修正历史错误误报和恢复交互，统一相关设置 UI，并基于取证优化偶发 Git 超时。技术栈沿用 Tauri 2、React、TypeScript、Rust 和当前固定版本 DSH。

执行时使用 executing-plans 逐项实施；子 Agent 须符合项目指定模型约束，否则当前会话执行。本文不授权提交、推送、发布、真实仓库 Git 写入或真实项目 ACL 修复。

### 1.1 取证结论与边界

- 截图对应旧会话的第 1 轮为 `UND_ERR_CONNECT_TIMEOUT`，第 2～4 轮正常完成。仅读取轮次结果取证，不将用户消息正文或凭据复制到文档、日志或测试资产。
- `host.ts` 恢复持久事件时重新投影历史失败；`useAiWorkspace.ts` 的 `accept` 将错误写入全局 `error`，后续完成或空闲不清除它。真实事件处理函数的内存复现证明：成功后及重读相同历史后，错误仍可见。
- `reconnect` 当前重建订阅、重读历史，不测试模型连通性；同一历史错误重放使按钮表现为没有效果。
- 老大确认启动时也出现同一连接超时码。历史误报已确认，真实首次建连偶发超时的网络原因尚未确认；启动及历史读取不等于模型健康检查。
- 核心单用例和原生切分支测试曾在 `status` 阶段真实超时。普通读取的配置安全探测与业务命令共享预算，带业务总期限的路径还受单进程上限约束。不能将这些本地读取失败直接归因为 GitHub 网络、杀软、磁盘或系统负载。
- 上轮核心全套未通过；原生 AI 回归为 6 通过、1 失败、3 默认忽略，本机模拟模型完整工具链另有 1 项通过。见 [验证记录](verification.md)，本轮不得抹除历史失败。

设置区沿用 GitMaster 设置控件，AI 会话内沿用已有 DSH 色板。样式限定作用域，不通过全局 button 规则改变其他页面。验收覆盖 1120×760、860×620、125% 缩放、深浅色及键盘焦点，长路径与按钮不得重叠。

## 3. 错误状态与历史恢复

### 3.1 状态来源分离

| 来源                             | 展示规则                                                           |
| -------------------------------- | ------------------------------------------------------------------ |
| 历史轮次失败                     | 留在对应轮次，更晚成功后不占用底部恢复提示                         |
| 当前请求失败                     | 关联会话、运行代次、runId 和轮次，表达该次请求失败，不宣称持续离线 |
| 历史读取、宿主或后台任务读取失败 | 表达实际操作失败，提供匹配动作，不翻译为模型网络故障               |
| 主动连接测试                     | 只表示所选模型最近一次测试结果，带测试时间，不作为永久健康状态     |

保留已有 HTTP、证书、DNS、限流等错误识别及具体错误码。未知异常保持通用请求失败，不猜测根因，不隐藏真实错误。

在聚焦的 `.ts` 模块中定义状态与纯推导；副作用在 hook，`.tsx` 只渲染：

| 类型                | 设计字段                                                                                                                           |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `AiIssue`           | `scope: history / runtime / model-request / job`；`code`、`message`；已知的 `sessionId/runtimeEpoch/runId/turn`，未知上下文为 null |
| `AiHistoryState`    | `idle / loading / ready / failed`，与 Agent 运行状态独立                                                                           |
| `AiConnectionCheck` | `idle / testing / succeeded / failed`；固定测试的 `providerId/modelId/revision`；结束时间 `checkedAt`，失败信息 `AiFailure`        |

连接测试状态只存内存。切模型、相关配置保存、切会话/项目后清除不匹配结果；异步结果校验上下文与请求代次，迟到结果不得覆盖新上下文。未测试不显示断线。

### 3.2 恢复规则

1. 历史页摄入与实时订阅摄入分开，复用 `runtimeEpoch + sequence` 去重；历史摄入不触发当前全局故障副作用。
2. 读取完成后结合最后一轮终态与后端运行状态推导提示。最后一轮失败可提示“上一轮请求失败”；更早失败留在时间线，不显示“当前模型已断开”。
3. 当前失败在对应轮次可见；后续新轮次成功后清除过期的当前提示，保留历史失败事实。
4. 首次恢复显示“正在加载对话…”，不逐条闪现旧错误。手动重载保留原消息、草稿与滚动位置，缓冲分页完成后合并发布。
5. 订阅与补读交错时按代次和序号合并；历史结果不能覆盖更新的实时状态。所有回调隔离项目、会话和恢复代次。
6. 恢复失败保留已有内容并提供重载。运行中、等待审批/回答时重载，不将任务改为空闲，不丢失有效运行标识、审批、问题和后台任务。

### 3.3 读取接口

`read_ai_session(repositoryId, sessionId, after)` 参数保持不变，现有 `AiSessionPage` 增加：

| 字段           | 类型           | 用途                                              |
| -------------- | -------------- | ------------------------------------------------- |
| `runtimeEpoch` | string         | 空事件页也能识别宿主代次                          |
| `activeRunId`  | string 或 null | 恢复当前运行标识，空闲时为 null，不从历史错误猜测 |

保留 `session/events/status/nextSequence/more`。共享类型集中定义，Node 返回、Rust 透传和前端同步更新，不改变上游 JSONL 格式或清洗用户历史。每页运行状态与标识在同一次读取中捕获。

恢复期间代次改变则丢弃旧缓冲，对新代次最多自动重建一次纯读取；反复变化显示宿主恢复失败，禁止无限重连。恢复订阅成功只表示记录同步正常，不代表模型连通。

## 4. 恢复按钮与启动交互

### 4.1 动作矩阵

| 场景                                 | 提示与动作                             | 成功条件                                               |
| ------------------------------------ | -------------------------------------- | ------------------------------------------------------ |
| 历史读取失败                         | “对话记录加载失败”＋“重新加载记录”     | 补读、订阅及运行状态核对完成                           |
| 宿主停止或运行时读取失败             | 对应原因＋“重新连接会话”               | 沿用现有可重试启动入口完成恢复，旧进程回收中仍阻止重启 |
| 当前或上一轮模型网络失败             | 对应轮次原因＋“测试模型连接”           | 用户主动测试得到明确结果，不重发历史输入               |
| 认证、余额、权限、接口或模型配置错误 | 原因＋“打开模型设置”                   | 打开相关设置，打开本身不宣称故障已解决                 |
| 后台任务读取失败                     | “后台任务状态读取失败”＋“重新读取状态” | 只恢复状态读取，不重新执行命令                         |

其他请求失败保留具体原因，允许用户编辑后重新发送，不强行套用网络测试按钮。本轮不增加自动重试本轮或一键重放历史任务，避免重复工具、Git 写入或 Shell 执行。

- 错误区域采用短标题、原因、操作的布局；恢复动作使用有明确点击区域的次按钮和现有刷新图标，不混在红色正文中。
- 重载中显示“正在加载…”，测试中显示“正在测试…”，防止重复操作。成功显示记录已加载或“本次模型连接测试通过”；失败显示本次原因并恢复操作能力。
- 测试通过不删除历史错误，不保证后续请求和工具必然成功。重载保留草稿、滚动位置与已有消息，不能以无变化或空白代替结果反馈。
- 复用 `test_ai_provider(providerId, modelId)` 的 30 秒 / 16 token 预算。入口说明“会发送最小模型请求，可能产生 API 费用”，不自动探活。
- 测试固定当前选择的模型及配置 revision，不用供应商第一项代替。AI 任务或另一测试运行中禁用并说明原因，后端忙碌门禁保留。
- 切换上下文或卸载后忽略迟到结果；不新增测试取消协议，后端请求遵守既有有界结束及退出回收。

### 4.2 启动规则

启动、进入 AI 页面、打开旧会话与重载历史均不自动测试模型，不发送付费探活请求。分别呈现项目、宿主和历史的实际加载状态，未测试不下在线/离线结论。“第 1 轮失败、后续成功”的历史在启动恢复和重开时都不显示当前连接失败。

修复历史误报后如仍有首次真实模型请求超时，再按连接阶段、代理配置来源、网络就绪及耗时取证。不得关闭 TLS 校验或安装证书掩盖问题，继续启用系统证书信任。

## 5. Git 超时排查与优化

### 5.1 基线与诊断

复用 `diagnostics.rs` 的关联 ID、父子阶段和脱敏日志，补充固定白名单的安全配置探测、预算分配及耗尽来源；沿用已有排队、进程准备、创建、等待、管道排空和回收阶段，不另建日志框架。

记录业务与固定命令类别、队列等待、剩余预算、配置探测和实际命令耗时、取消/超时阶段及回收结果。禁止记录命令原文、参数、绝对用户路径、环境值、配置正文、凭据 URL 或 Git 输出；沿用现有日志级别设置。

独占采样比较受管理执行器与直接系统 Git 的同等只读操作，并覆盖受控延迟、普通临时仓库及链接工作树。记录调用次数、P50、P95、最大值和超时数；不把构建时的高负载作为唯一基线。

### 5.2 优化顺序与安全边界

1. 确认属于排队、配置探测、进程创建、Git 执行、I/O 排空还是上层期限耗尽；核对单进程上限和业务总期限，不能仅凭 status 标签认定 Git 本体慢。
2. 核对现有队列、缓存与失效逻辑，去除有证据的重复 UI 刷新或相同读取，优先复用；不存在重复则不新增合并层。
3. 修正已证实不一致的期限传递和归因，保留有限总期限、取消和进程树回收。既有回收预算不能因主期限耗尽被跳过。
4. 如仍需调整时长，仅针对采样证明不足的路径，先在本文记录旧值、新值、范围与依据，再实施并验证有界等待；不统一翻倍超时或动态无限延长。
5. 本轮不增加跨命令的有效 Git 配置长期缓存，不省略安全配置探测；写计划准备、批准前的状态、配置与指纹核验不得用过期缓存替代。

禁止切换无保护执行器、关闭 Job 管理、执行外部 filter/diff/textconv/hooks、去掉仓库队列或自动重试真实 Git 写入。未知写入结果不能报告成功。本轮不新增通用自动重试层来掩盖持续超时。

### 5.3 验收口径

实施取证补充（2026-11-13）：独占基线 1 项通过，受管理读取与系统 Git 均有实际耗时波动，完整打开约 5.5～14.7 秒。预算回归已复现：配置探测消耗 8 秒时，旧的 10 秒组合期限仅给后续状态命令留下约 2 秒，尽管各阶段都未超过单进程上限。采用定点修正：仅普通 status/diff 只读入口的组合期限从 10 秒改为 20 秒，配置探测和实际命令仍分别最多 10 秒；其他只读、写入和网络上限不变。显式业务总期限继续优先约束，不能用新组合期限越过它。这修复已证实的预算争用，不预先宣称所有物理执行变慢的原因已经解决。

- 普通临时仓库和链接工作树各进行 5 次冷打开、20 次连续状态读取；相同环境独占记录优化前后结果。常规受控用例应零超时，P95 不得因改动明显退化。
- 受控延迟分别触发配置探测、命令执行和排队超时，归因匹配；取消及超限后进程树有界回收。复用测试夹具，不增加生产任意可执行入口。
- 复测上轮失败的核心分支用例，以及原生暂存→提交→创建→切换分支链；写入只在临时仓库，验证只读拒绝和逐次确认。
- 覆盖准备与批准间配置/引用改变、外部过滤器配置、同仓库竞争及后台任务租约交接，不削弱拒绝条件。
- 无法稳定复现或优化后仍失败时，记录数据、已知阶段、未确定部分及剩余门禁；不能将偶尔成功或扩大预算后的单次通过写成彻底解决。

## 7. 实施计划

### P0：回归与基线

- [ ] 用合成事件复现“失败→成功→重开历史”和“清空提示→重读→旧错误重现”，测试先证明旧行为存在问题。
- [ ] 覆盖最后一轮失败、读取失败、宿主中断、跨会话迟到结果和任务读取失败，不复制用户会话。
- [ ] 独占记录 Git 两个既有失败用例及阶段基线，不与构建或完整回归同时计时。

### P1：历史与错误状态

- [ ] 接通共享字段，区分历史/实时摄入，去重合并并推导末轮提示；验证上一轮失败的措辞。
- [ ] 验证分页中间旧失败、末页成功不闪现故障；覆盖事件交错、重复、空页及代次变化。
- [ ] 验证恢复失败保留内容与草稿，运行中、审批/问答等待时重载后仍可继续处理或停止。
- [ ] 验证冷启动与历史恢复不产生模型请求，最后成功的旧会话无当前断线提示，历史错误仍可查看。

### P2：恢复交互与设置 UI

- [ ] 实现动作矩阵、进行中防重复、明确结果；测试固定当前模型，成功/失败/忙碌/超时均有反馈。
- [ ] 验证测试中切会话、项目、模型及配置，迟到响应不污染；历史重载、任务状态重读与设置入口不调用模型。
- [ ] 完成权限设置行、状态、路径及加载态；验证无项目、切项目、失败后再次检查、不经确认不修复。
- [ ] 完成深浅色、两尺寸、125% 缩放及键盘检查，确认长路径、错误和操作不重叠或遮挡。

### P3：Git 最小优化

- [ ] 根据阶段证据实施最小修改，记录选择、排除假设及预算变更依据，不凭失败码猜根因。
- [ ] 完成延迟、取消、配置变化、队列竞争和回收回归，再做两个仓库类型的前后对照采样。
- [ ] 复测核心分支失败用例与原生完整 Git 写链，仍失败则保留未通过，不能用单次成功覆盖。

### P4：集成与交付检查

- [ ] 通过 pnpm typecheck、pnpm build、pnpm format:check、cargo fmt --all -- --check、cargo check -p gitmaster-desktop。
- [ ] 运行 pnpm test:agent、pnpm test:agent:bundle 及相关定向回归；核心全套以 cargo test -p gitmaster-core -- --test-threads=1 独占运行，失败如实记录。
- [ ] 顺序准备 Agent 资源并执行 pnpm tauri build --no-bundle，禁止同时修改/复制运行包资源；原生模拟模型验证终端、Git、Skill 与确认暂存。
- [ ] 实际 Windows Release 检查旧会话、重载、连接测试交互、设置和启动；使用本机模拟模型制造可控失败与恢复，不依赖开发服务器证明 Release 可用。
- [ ] 不启用上轮被自动审批拦截的远程调试方案，优先普通启动和原生操作；物理 Escape 中止后立即停止并记录范围与偏好恢复情况。
- [ ] 更新验证记录，保留既有本地改动，不提交、不推送；本轮临时改动的偏好应恢复并核对，不擅自修改上轮遗留的用户当前设置。

## 8. 最终验收与授权边界

| 场景                            | 必须结果                                                          |
| ------------------------------- | ----------------------------------------------------------------- |
| 历史先失败、后成功              | 保留消息和历史失败，不显示当前连接失败                            |
| 最后一轮失败、当前空闲          | 表达上一轮失败，可主动测试，不宣称持续离线                        |
| 历史失败后重载                  | 有加载反馈，保留内容/草稿；成功清除本次读取错误，失败显示本次原因 |
| 模型真不可连接→恢复             | 主动测试先失败后成功，不自动发送历史输入或执行工具                |
| 宿主停止、冷启动或回收中        | 归因准确，恢复不越过回收门禁，不误标模型离线                      |
| 当前失败后新轮次成功            | 当前提示过期，历史失败仍可查阅                                    |
| 审批/问答等待时重载、运行中测试 | 不丢上下文、不重复执行；忙碌测试被阻止且原因可见                  |
| 切上下文后的迟到响应            | 不回填新上下文、不覆盖新错误和选择                                |
| 权限检查与模型状态              | 分离表达，检查不写权限，修复仍明确确认                            |
| Git 慢、超时或取消              | 阶段可定位、等待有界、回收正确，未知写入不报成功                  |

本机模拟模型验收不调用真实付费 API。真实服务商测试如需执行，另行明确当次范围及费用授权。真实项目 ACL 与仓库写操作仍按原授权流程。macOS 原生、干净系统、安装器及签名无法在当前环境覆盖的部分必须标注未测。
