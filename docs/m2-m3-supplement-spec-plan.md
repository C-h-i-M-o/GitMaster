## 2. 界面与交互需求

### 2.1 提交图分支头

- 每个真实 tip 使用独立圆角标签，标签位于对应节点上方；本地/远端引用使用图标和文字区分，不能只靠颜色。
- 当前分支标签增加细分隔线与弱化 HEAD 标识；detached HEAD 单独显示，不误标某个普通分支为当前分支。
- 同一 OID 多个引用：当前本地分支优先，其余稳定排序；默认展示前两个与“+N”，点击可查看全部完整名称。名称过长省略但提供完整提示和键盘访问。
- 标签宽度按实际文本测量并设上限，纳入画布裁剪和命中范围，避免固定宽度截字。标签与相邻节点重叠时允许展开引用列表查看，不改变真实 Git 拓扑。
- 关闭提交说明显示时仍保留分支头与 HEAD。拖动、缩放、分页后引用保持绑定原 OID，不把“属于某分支”当作提交固有属性。

### 2.2 底部多标签面板

- 标签栏支持激活、关闭、横向滚动和“+”菜单；每次新建选择终端或操作记录。底部可折叠、拖动调整高度；折叠不关闭会话。
- 终端标签独立会话，标题含 shell 与项目简称；操作记录标签共享同一份数据，可保留各自筛选、滚动与选中任务，不重复启动任务轮询。
- 默认打开一个操作记录标签，不自动启动 shell。终端具体能力及项目切换策略见第 9 节；推荐各会话绑定创建时的项目，切换项目不偷偷改变旧 shell 的目录。
- 操作记录使用“任务列表 + 选中详情”：列表展示动作、项目/分支、状态、开始时间、耗时；运行中置顶，其他按时间倒序。状态包括进行中、已完成、失败、待处理、结果未知。
- 详情将 checking/transferring/verifying 等事件按阶段归组，展示目标、结果、可恢复提示与诊断编号；不把同一任务每次轮询重复显示为新操作。
- 支持全部/进行中/失败筛选和名称查找。无操作、加载中、失败为空、多个任务、任务结果未知分别呈现；结果未知只能重新查询，不能引导重复写入。
- 建议仅保留当前应用会话最近 200 条已结束任务，每任务最多 100 条阶段事件；活跃任务不因数量限制丢弃。达到上限移除最旧已完成记录并说明保留范围，不持久化命令正文或原始输出。该上限为设计初值，需在验收中测量。

### 2.3 顶部刷新与同步远程

右上保留“刷新”“同步远程”及设置，移除“新建分支”“获取更新”“上传版本”；左侧新建分支保留。

**刷新：** 用户明确点击时同时读取本地状态并执行 fetch；不改变工作文件、不合并、不推送、不 prune。自动刷新、操作完成后的本地状态更新和焦点恢复不得调用这条联网入口，防止隐式反复 fetch。fetch 范围按第 9 节 Q3 执行。

无远端时仍完成本地刷新并显示“未配置远端，仅刷新本地”。网络失败不阻止可用的本地结果展示：分别记录本地刷新与远端获取结果、最后成功获取时间。连续点击合并为一个任务，fetch 完成后失效引用/历史/远端评估并按需读取。

全分支 fetch 成功后按远端名称保存本次实际下载的分支名称清单（`fetchedBranchNames`，未观测为 null，空远端为 []）。该清单与保留的本地跟踪引用分开：不 prune 仍可保留旧引用，但同步目标不在本次清单中时按目标缺失处理，不能因为旧 OID 与 HEAD 一致就宣告已同步。相同配置的会话刷新继承清单；配置摘要变化则使观测清单及时间失效，下一次同步重新获取。

**同步远程：** 索引、工作区、未跟踪文件均为空，且有具名当前分支、无冲突或进行中的 merge/rebase 等状态时允许。未保存的编辑器草稿也阻止同步，提示先保存或放弃。禁用原因显示在按钮附近并支持键盘访问。

同步先获取目标最新信息，再核对工作区、当前 HEAD、分支、上游与配置，按新结果决定动作：

| 本地相对远端                                | 行为                                                 | 完成判定                                               |
| ------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------ |
| 一致                                        | 不执行写入，提示已经同步                             | 最新评估 equal                                         |
| 仅落后                                      | 显式 fast-forward-only 更新当前分支及工作区          | HEAD 与目标 OID 一致，工作区核验完成                   |
| 仅领先                                      | 普通非强制推送当前 HEAD 至该分支对应远端目标         | 重新查询远端目标确认写入；后续远端又变化时展示最新差异 |
| 既领先又落后                                | **已由用户确认：停止同步，提示通过现有合并流程处理** | 不自动 merge/rebase/push                               |
| 无上游、远端目标不存在或映射不唯一          | 不猜测 origin/同名分支；转目标设置引导               | 无上游时弹出目标设置页，规则见下文                     |
| detached/unborn、无共同祖先或缺对象无法评估 | 不执行同步并显示原因                                 | 不伪造成功                                             |

只对当前分支执行拉取或推送：禁用 force、mirror、全部分支和自动推标签。复用现有显式 refspec 与认证规则，不使用裸 `git pull` 让本地配置暗中决定 merge/rebase。远端变化导致拒绝时重新评估，不自动覆盖或重试推送。

同步推送复用已有普通推送传输与核验，但增加独立的同步策略：目标从后端当前分支上游解析，准备及每次执行校验均要求具名分支、无本地修改和进行中操作；已有上游目标在服务器消失时返回目标缺失，不能自动创建。旧手动推送保持允许上传已提交内容的原有语义。首次明确选择新目标的创建流程单独处理。

写请求增加不接受目标参数的 `syncPush` 与 `syncFastForward`，由后端读取当前分支上游。快进复用既有整合计划，交付前再次校验原配置与仓库快照，执行复用指纹及检出门禁；UI 仍须先完成 fetch 并按最新关系选择动作，不能将本地已有跟踪引用的评估当作已联网同步。

前端同步编排按 `checking → fetching → assessing → syncing → idle` 串行进行，任务必须完成且终态本地刷新结束后才能读取新远端会话及评估。获取前后绑定同一仓库、当前分支、HEAD 和上游名称；切换仓库/分支、出现本地修改、上游变化、获取失败或执行结果未核实均停止自动链，不自动重试写入。无上游及目标缺失进入设置状态，分叉进入可打开现有合并流程的提示状态。内部任务轮询继续复用既有控制器，不另起一套后台轮询。

无上游首次同步（用户已明确确认）：点击“同步远程”即弹出远端和目标分支选择页，明确显示“设置为当前分支上游并同步”；取消不写配置。后端校验当前分支、工作区及目标后，现存远端分支设置上游并重新评估同步；目标尚不存在时明确提示将创建远端分支，普通推送成功并核验后再设置上游。配置失败与网络结果分别展示，不能把远端推送成功误报成全部失败并诱导重复推送；设置上游仅限当前分支，不修改其他分支配置。

配置阶段使用独立 `setUpstream` 任务，输入当前远端会话 ID 与目标分支名；准备绑定仓库快照、完整配置摘要及目标跟踪引用 OID。执行前重复核验，使用 Git 自身的设置上游命令并读取实际结果，不拼接 shell；配置写入已尝试但无法完整核验时保留未知结果，不自动回滚或重试。现有目标必须对应所选远端的唯一跟踪映射，首次创建远端目标仍须先完成普通推送。

首次发布使用独立 `publishBranch` 请求：目标由用户明确选择，准备查询服务器后必须确认目标不存在；若已存在则返回 TARGET_EXISTS 重新评估。执行只普通推送当前干净具名分支的固定 HEAD，核验成功后再获取目标并设置上游，不因配置失败重发已成功的推送。

分叉提示保留“打开合并流程”入口；删除旧顶栏按钮不能使已实现的合并/冲突处理失去可达入口。

### 2.4 本地修改与二级差异面板

保留未暂存、未跟踪、已暂存三组；冲突继续独立入口。勾选状态与点击查看文件独立。

| 勾选状态                 | 合并按钮         | 是否可点                         |
| ------------------------ | ---------------- | -------------------------------- |
| 无选择                   | 暂存所选         | 否，提示先选择文件               |
| 仅未暂存和/或未跟踪      | 暂存所选（数量） | 是                               |
| 仅已暂存                 | 取消暂存（数量） | 是                               |
| 暂存来源与已暂存同时勾选 | 暂存 / 取消暂存  | 否，明确提示不能同时处理两种方向 |

- 同一 MM 文件的两侧分别计入对应选择，不能因路径相同自动合并勾选。刷新快照后清理失效选择。
- 提交说明位于底部；合并暂存按钮与提交按钮同一行固定可见。提交包含整个索引，不以勾选列表过滤提交，旁边显示真实已暂存数量。
- 点击文件时，从右侧展开第二层详情，保持第一层文件列表、选择、提交草稿和滚动位置。宽窗口并排，窄窗口第二层覆盖第一层，提供返回按钮；无需打开操作确认模态框。
- 第二层头部显示完整路径、比较侧、增删统计与关闭按钮。默认采用图 2 的统一行内 diff：旧/新行号、红色删除、绿色新增、上下文折叠、横向滚动和文本复制；未知统计不显示为 0。
- 未暂存比较 index→工作区，已暂存比较 HEAD→index；unborn 的已暂存比较空树→index，未跟踪显示新增内容。部分暂存、重命名、删除、空文件、无尾换行不得混淆比较侧。
- 此面板只读，不提供逐行暂存或编辑；二进制、不可解码和截断必须显式说明。快速换文件或暂存后迟到响应不能覆盖当前详情。

### 2.5 项目文件查看、编辑与外部打开

- 项目文件区域采用“左正文、右文件树”，顶部文件标签、面包屑、保存与外部打开入口；文件树可折叠、按路径筛选，文件夹先于文件。多个文件标签独立保存滚动、光标和草稿。
- 仅查看和编辑已有普通文本文件；支持手动保存、Ctrl/Cmd+S、撤销/重做、查找、行号、基本语法高亮。不提供新建、删除、移动、重命名、另存为、自动保存或运行脚本。
- 保存只写工作文件，不暂存、不提交。成功后更新文件版本并使相应本地修改/差异失效；失败保留草稿。
- 关闭脏文件、切项目、退出前提供保存/放弃/取消；文件外部变化时不覆盖草稿。保存前核对文件身份、原始内容版本与路径边界，变化时拒绝覆盖并允许重新读取；不自动合并草稿。
- 保留编码、BOM、换行和权限。首轮建议普通 UTF-8/UTF-8 BOM 且可无损往返的文本可编辑；其他编码、混合换行、符号链接、重解析点、子模块及超限文件提供只读说明与外部打开。具体文件覆盖范围见第 9 节。
- 大文件只读/差异性能继续遵循总计划第 12.6 节；完整编辑模型建议先以 2 MiB 为有界编辑初值，超过时只读，不把截断内容当完整文件保存。该限制不得降低正式版阅读目标。
- 外部打开的目标固定为当前项目根目录。建议首版支持系统文件管理器、已安装 VS Code、系统终端；其他软件不纳入首版外部打开列表。不照搬“Default app”含混语义，不增加另存为。
- 使用已有 opener 能力或受限原生启动适配，应用标识映射可信可执行程序，参数数组传入目录；前端不能提交任意 executable/arguments。未安装软件隐藏或明确禁用，不自动下载，不修改系统默认程序。

“取消弹窗”只改变交互层，不取消 prepare→校验→execute→核验。预检后状态或方向改变则停止并更新界面，不能把原点击授权套到另一目标。失败在相关区域提供可操作原因，避免同一个错误同时出现在 toast、模态框、底栏三处。

## 3. 技术方案与权限边界

### 3.1 组件选型

终端建议评估 xterm.js 与 FitAddon，Rust 端评估 portable-pty；编辑器优先评估 Monaco 的有界文本模型与本地 Worker，差异展示复用后端真实 patch 数据。依赖版本、许可证、包大小和 WebView 兼容性在获安装授权后锁定，不在本轮下载。

- [xterm.js 插件说明](https://xtermjs.org/docs/guides/using-addons/)：用于成熟终端展示与尺寸适配。
- [xterm.js 流量控制](https://xtermjs.org/docs/guides/flowcontrol/)：用于设计输出背压，不能无界堆积 IPC 输出。
- [Monaco 官方说明](https://github.com/microsoft/monaco-editor/blob/main/README.md)与[ESM/Worker 集成](https://github.com/microsoft/monaco-editor/blob/main/docs/integrate-esm.md)：用于评估编辑器复用；不引入整套 VS Code 或扩展市场。
- [portable-pty 官方文档](https://docs.rs/portable-pty/latest/portable_pty/)：作为 Rust 跨平台 PTY 候选，不能以文档存在替代 Windows/macOS 实机验证。

编辑器、Worker、终端资源均随包提供，不依赖 CDN、Vite 开发服务器或联网运行。

### 3.2 已确认的完整终端能力与边界

用户已明确确认终端允许任意命令并支持终端设置，为旧 AGENTS 与 M2/M3 的“无任意命令接口”规则增加独立终端例外，不再重复询问该项授权。用户主动打开 shell 并输入命令；Git 按钮仍走原受限接口，不转为 shell 字符串。本次已获开发批准，功能尚未实施。

推荐默认 Windows 优先已安装 pwsh，未安装时使用系统 Windows PowerShell；macOS 使用可验证的用户登录 shell。PTY 仅向当前窗口签发 sessionId，支持输入、输出、resize、退出；禁止仓库内容触发创建终端或自动输入命令。

shell 具有用户本机权限，应用不能保证其命令经过 Git 队列或危害确认；终端与外部编辑器产生的改动按外部变化处理。Git 按钮写入前仍重新检查快照，遇到锁或变化拒绝。不要宣称可对任意 shell 命令提供全仓库互斥。

终端输出留在内存终端缓冲，不进入诊断日志/操作历史持久存储；不记录输入，禁止输出转 HTML 或自动执行 OSC 指令打开应用、写剪贴板。建议每终端 5,000 行回滚、最多 8 个活跃终端，输出通道设字节上限与背压；达到限制显示原因。关闭会话释放 PTY、子进程和订阅，不能留下无主 shell。跨平台子进程树回收必须实测。

### 3.3 文件与任务边界

Git/文件保存使用独立 Rust 核心，桌面层负责 IPC 和系统打开。PTY 的系统实现放桌面独立模块，不让核心依赖 Tauri 或窗口。

文件保存使用后端签发 documentId 与版本令牌，验证当前仓库与路径，不接收任意绝对路径。采用受控替换与写前复核，处理 Windows 文件占用及失败清理，保留原文件；承认应用锁无法锁住所有外部工具，不宣称可消除所有外部竞争。

任务历史以 operationId 聚合。仓库切换后当前视图不接受旧会话结果，但已发起任务可以更新其所属项目的记录；关闭记录标签不取消 Git 任务。复用一个操作数据源，避免每标签创建重复轮询。

## 4. 拟新增或调整的数据契约

以下是设计接口，具体实施状态见进度记录。TS 与 Rust 同步强类型定义；所有时间使用毫秒时间戳，所有 ID 为后端签发的不透明字符串，枚举不以自由文本代替。

远端只读状态增加 `branchUpstreams`：每项含 `branchName`、`remoteName`、可空 `remoteId`、`targetRef` 和 `trackingRef`。映射由 Git 的上游格式字段解析，不按显示名称中的斜杠拆分；目标跟踪引用尚不存在时仍允许返回已解析配置。此字段只提供观测信息，不授予写入权限；同步执行前仍须在后端校验配置完整性、唯一性和快照时效。不能把未解析到映射直接认定为用户从未设置上游。

同步入口增加 `read_sync_target(repositoryId, snapshotId)`：复用当前远端会话，返回 `SyncTarget { repositoryId, snapshotId, branchName, upstream }`。upstream 区分 `missing`（remote/merge 均无配置）、`configured`（remoteId、targetBranchName、可空 remoteBranchId）及 `unresolved`（配置不完整、重复、指向本地仓库、非分支目标、远端或映射缺失）。跟踪引用尚未下载不等于没有上游。该接口只读，不联网；调用前后复核真实仓库快照与配置，并要求具名已提交分支、工作区和索引干净、无进行中操作。它只提供同步入口目标，不能代替 fetch 后评估及写入前再次校验，也不能授权覆盖 unresolved 配置。

直接提交前，仓库快照须在 Rust 内部保存完整索引条目摘要（不传前端）。状态读取前后比较 `ls-files --stage -z` 结果，读取期间变化则拒绝生成混合快照；提交准备时比较页面快照与最新摘要，状态字母相同但 blob 已替换也返回过期。执行阶段继续沿用完整写入指纹校验。额外只读查询纳入原总期限，大目录性能需重新测量。

| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BottomTab             | tabId、kind（terminal/operations）、repositoryId；terminalSessionId 仅 terminal 分支存在；筛选与滚动为前端视图状态                                                                    |
| TerminalSession       | sessionId、repositoryId、displayCwd、shellLabel、state（running/exited/failed）、exitCode（可空）                                                                                     |
| TerminalOutput        | sessionId、sequence、字节块；按顺序解码跨块 UTF-8，关闭后丢弃迟到事件                                                                                                                 |
| OperationHistoryEntry | 现有 handle/kind/progress/result，加 displayTarget、startedAt、finishedAt（可空）、有界阶段事件；所有目标描述脱敏                                                                     |
| RemoteSyncAssessment  | repositoryId、snapshotId、branchId、headOid、upstreamRefId、remoteId、targetOid、ahead、behind、fetchedAt、decision（equal/fastForward/push/diverged/blocked）、blockedReason（可空） |

- `TerminalProfile`：profileId、name、executablePath、args（string 数组）、cwd（project/home/fixed 判别联合，fixed 带路径）。仅用户保存的配置可用于启动。

## 9. 已确认决策与实施授权

本地差异上下文补读：默认每处变化前后 3 行，用户可按 20、100、500、2,000 行逐级加载；`read_file_diff` 增加可选 `contextLines`，核心拒绝超过 2,000 的请求并继续保留字节/行数上限。补读绑定原文件、比较侧和仓库快照，切换文件或刷新后迟到结果作废；已截断结果不宣称完整上下文。

核心分支测试等待采用生产操作预算加有限终态交付余量，不能在任务仍允许执行时提前判定失败。只修正测试等待，不放宽生产超时、成功结果或仓库状态断言；已确认使用错误等待时限的全量运行须记录中止原因并重新验证。

编辑器重新读取：脏文件须先明确放弃草稿；旧草稿保留到磁盘读取成功。读取失败、读取过程中继续输入、切换项目或关闭标签均不覆盖原草稿；重新读取不执行文件写入。保存开始后使在途重新读取失效，避免成功保存的基线被旧读取结果替换。

编码边界实施：混合 LF/CRLF/CR 的文件继续通过只读预览查看，完整编辑文档入口返回 `FILE_EDIT_LINE_ENDING` 并说明使用外部编辑器，不把会统一换行的编辑模型用于此类文件。原 BOM、单一换行与无尾换行仍按字节往返验证。

设置校验反馈：错误摘要标明分类及终端配置序号，点击后切换分类并聚焦对应控件；输入修改后沿用统一草稿错误清理。删除默认终端配置前必须由用户先选另一默认项，界面与状态更新函数均拒绝自动替换。

底部面板尺寸验收：分隔条辅助功能同时提供当前高度、最小值和随工作台变化的最大值；窗口缩小时将现有面板高度收回可用范围，不遮挡主工作区。

操作记录归属：执行前捕获预览对应的项目路径、源分支及可用目标摘要，后续进度沿用该值，不从当前页面分支反推。恢复的旧任务若没有已捕获目标，只显示仓库身份及“历史目标未记录”，不伪造来源；已有记录继续保留原摘要。

手动刷新反馈：区分远端获取（未执行、进行中、成功、失败、未核实）与本地读取（未执行、进行中、成功、失败）。等待本次获取任务及终态回调完成后展示真实结果；准备失败可单独读取本地，未知任务不重复发起获取。最近成功获取时间仅来自后端会话元数据，失败不更新，界面转换为可读本地时间。

编辑控制器实施：多文件草稿按当前仓库路径归属；保存前从最新清单取得文件 ID 并重新读取完整文档，基线或 BOM 变化时拒绝覆盖。保存只确认已核实成功结果提交的文本，保存期间的新输入继续保留；成功后刷新失败须提示文件已保存。关闭脏文件等待保存/放弃/取消选择，仓库切换不能直接清除脏草稿；异步读取迟到结果不改变当前标签。
